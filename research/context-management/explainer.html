What each bot sees, and how work moves between them

An interactive guide to how JJ Bot builds context for each model call today, measured on the real engine, and what the proposed designs would change. Sections 1–3 explain the mechanics; section 6 has the results of 50 real-model runs (openai/gpt-6-luna, $0.15 in total).

1Every model call resends the whole stack

A model call does not remember the previous one. Each call sends the system prompt, every tool definition and the session's entire transcript again. Click a bar to see what one call contained.

Tokens are estimated as characters ÷ 4 of exactly what the engine hands to the provider (harness.ts). The fixed part, system prompt plus tool definitions, is about 2,000 tokens and makes up 68–97% of each call here. It is cheap only if the provider can cache it, which requires those bytes to stay identical.

2Play a task: who wakes, and what reaches whom

Each box is an execution session: one bot doing one piece of work in this task, with its own transcript and inbox. Ada, Grace and Linus are the bots (personas) running them. Ada's box is the task's root (coordinator) session; each delegate creates a new child session. A session runs in several runs: it wakes, works, then waits.

Every input lands in a session's inbox. Briefs, results and the user's messages wake the session. A teammate's message waits until something else wakes it, and it is never read if the recipient's session has already finished.

Source: services/messages.ts:139-173 (delivery and waking), worker/collab-tools.ts (delegate, message), worker/outcomes.ts:252-289 (results).

4Three design options

Recommended · digest pushed, tools on request

A · Task context

  • task_log, read_entry, read_report: read-only lookups any bot in the task can call
  • Structured briefs, with the files a worker owns and what to report
  • Results point to files and are clipped; the full text is one call away
  • A message to a finished session becomes an error

E1: a short digest pushed into each brief cost no more than today and passed 5/5. Pull tools also passed 5/5, and workers did use them, but they cost 40% more tokens. So push the digest, and keep the tools for what a brief cannot anticipate.

Downgraded by E3

B · + Decision log

  • note(text, kind) appends a decision, interface, todo or risk
  • The latest titles reach every session at its next turn
  • Replaces most peer-to-peer messages

E3: negotiating through a shared NOTES.md was the most expensive variant (5× the hub's tokens, 2.2 fix delegations per run). The coordinator simply deciding the interface up front was cheapest. Revisit only as a record of decisions, not as a channel.

Take C2 with A

C · + Warm re-delegation

  • C1: reopen the bot's finished session with the new brief
  • C2: start a fresh session whose brief includes the bot's previous brief and report

E2: both warm variants used 20–30% fewer tokens than a fresh session, with the same success within noise (4/5 each). C1 was the only one that never got the codeword wrong. C2 needs no new session semantics.

Also from the experiments: the coordinator should fix shared interfaces and conventions in the briefs (E3). Context hygiene pays off most on the coordinator, which used 77% of all prompt tokens in E0. Keep the system prompt byte-stable, and clear old tool results before #62 compaction runs.

5What other systems teach

Orchestrator / workerAnthropic's research system uses about 15× the tokens of chat; token usage alone explains 80% of performance variance. Subagents return 1–2k-token summaries and write large outputs to files. opened
Peer chatterEarly versions of that system had subagents "distracting each other with excessive updates". AgentPrune and S²-MAD remove most inter-agent messages at little or no loss in accuracy. opened / search
Shared decisionsCognition: "actions carry implicit decisions"; keep writes single-threaded, and use reviewers that start with a clean context. search
Buffered broadcastAutoGen's SelectorGroupChat holds a broadcast for each agent until that agent next speaks, the same as JJ's "wait for the next turn". AG2 later moved to a hub with typed channels. repo
Just-in-time contextSkills load a one-line index first and the full content on demand. Anthropic's context editing (clearing old tool results) cut tokens by 84% on a 100-turn eval. opened
Failure modesMAST: information withholding and ignoring another agent's input are their own inter-agent failure categories, and verification is a third. repo

6What the real-model experiments showed

50 runs on openai/gpt-6-luna, 5 per variant. A script checked each final workspace; a bot's own claim never counted as a pass. With 5 runs, a one-run gap (4/5 against 5/5) is noise. The token and cost differences, and E3's large gaps, are the signal.
